Claude Building the workflow loop and alert-triggering checks Here’s the upgrade. It adds three things: Restock log. Every time a store’s status changes, for example from unavailable to available, the bot adds a line to restocks.csv in your repo with the time in Central, the store and its distance. After a few days you can open the file and look for patterns. Daily “still alive” ping. Once a day, after 8am, you get a quiet notification like “142 checks, 0 errors, 2 stock changes since last update”. Night mode. From 10pm to 7am, it checks only once about every 15 minutes instead of every minute, because stores aren’t releasing pickup stock then. To do this, the bot saves a small state.json file and commits it to the repo after each run. You’ll see a lot of “Update stock log” commits. That’s expected, and it also helps keep the repo active. check.py python import os, json, csv, time, datetime, requests from zoneinfo import ZoneInfo PART = os.environ["PART"] ZIP = os.environ["ZIP"] TEST = os.environ.get("TEST") == "true" TOPIC = "aryak-duo-256-night-sky" MAX_MILES = 50 GAP = 60 TZ = ZoneInfo("America/Chicago") STATE_FILE = "state.json" LOG_FILE = "restocks.csv" BAG = "https://www.apple.com/shop/bag" BUY = "https://www.apple.com/shop/buy-iphone" headers = { "User-Agent": "Mozilla/5.0 (iPhone; CPU iPhone OS 18_0 like Mac OS X) " "AppleWebKit/605.1.15 (KHTML, like Gecko) Version/18.0 " "Mobile/15E148 Safari/604.1", "Accept": "application/json, text/plain, */*", "Accept-Language": "en-US,en;q=0.9", "Referer": "https://www.apple.com/shop/buy-iphone", } def now(): return datetime.datetime.now(TZ) def push(title, msg, priority="urgent", actions=None, click=BAG): h = {"Title": title, "Priority": priority, "Click": click} if actions: h["Actions"] = actions requests.post(f"https://ntfy.sh/{TOPIC}", data=msg.encode(), headers=h) def log_event(store, miles, status): new_file = not os.path.exists(LOG_FILE) with open(LOG_FILE, "a", newline="") as f: w = csv.writer(f) if new_file: w.writerow(["time", "store", "miles", "status"]) w.writerow([now().strftime("%Y-%m-%d %H:%M"), store, miles, status]) # Load saved state try: with open(STATE_FILE) as f: state = json.load(f) except Exception: state = {} state.setdefault("stock", {}) state.setdefault("checks", 0) state.setdefault("errors", 0) state.setdefault("events", 0) # Night mode: 10pm-7am, roughly one check every 15 minutes t = now() night = t.hour >= 22 or t.hour < 7 if night and not TEST and t.minute % 15 >= 5: print("Night mode: skipping this run") raise SystemExit(0) CHECKS = 1 if (TEST or night) else 10 alerted, failures = set(), 0 for i in range(CHECKS): try: r = requests.get("https://www.apple.com/shop/retail/pickup-message", headers=headers, timeout=20, params={"parts.0": PART, "location": ZIP}) stores = r.json()["body"]["stores"] for st in stores: name = st["storeName"] miles = float(st.get("storedistance", 999)) info = st.get("partsAvailability", {}).get(PART, {}) status = info.get("pickupDisplay", "unknown") if not TEST: prev = state["stock"].get(name) if prev is not None and prev != status: log_event(name, miles, status) state["events"] += 1 state["stock"][name] = status in_stock = status == "available" or TEST if miles <= MAX_MILES and in_stock and name not in alerted: tag = "[TEST] " if TEST else "" push(f"{tag}Duo in stock: {name}", f"Night Sky 256GB at Apple {name} ({miles} mi). " f"Tap to open your bag, choose pickup at {name}.", actions=f"view, Open Bag, {BAG}; view, Buy page, {BUY}") alerted.add(name) state["checks"] += 1 print(f"Check {i+1}: {r.status_code}, alerted: {sorted(alerted) or 'none'}") except Exception as e: failures += 1 state["errors"] += 1 print(f"Check {i+1}: error {e}") if i < CHECKS - 1: time.sleep(GAP) t = now() # Failure alert, roughly once an hour while broken if failures == CHECKS and not TEST and t.minute < 5: push("Duo checker failing", "All checks failed this run. Apple may be blocking it.", priority="low", click="https://github.com") # Daily heartbeat after 8am today = t.strftime("%Y-%m-%d") if not TEST and t.hour >= 8 and state.get("last_heartbeat") != today: push("Duo checker: still running", f"{state['checks']} checks, {state['errors']} errors, " f"{state['events']} stock changes since last update.", priority="low", click="https://github.com") state.update(checks=0, errors=0, events=0, last_heartbeat=today) if not TEST: with open(STATE_FILE, "w") as f: json.dump(state, f, indent=1) check.yml yaml name: Duo stock check on: schedule: - cron: "3-58/5 * * * *" workflow_dispatch: inputs: test: description: "Send a fake in-stock alert" type: boolean default: false concurrency: group: duo-check permissions: contents: write jobs: check: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - run: pip install requests - run: python check.py env: PART: ${{ secrets.PART }} ZIP: ${{ secrets.ZIP }} TEST: ${{ inputs.test }} - name: Save log if: ${{ !inputs.test }} run: | git config user.name "duo-bot" git config user.email "duo-bot@users.noreply.github.com" git add -A git diff --cached --quiet || (git commit -m "Update stock log" && git pull --rebase && git push) After committing both files: The first normal run sends a “still running” ping straight away. That’s expected, and it confirms the heartbeat works. After that run, state.json should appear in your repo. restocks.csv only shows up after the first stock change, so don’t worry if it’s missing for a while. If the “Save log” step fails with a permission error, go to Settings, then Actions, then General, then Workflow permissions, choose Read and write permissions, and save. It could alert once when stock appears, then remind you only every 15 minutes while it’s still there, instead of every 5. It’s less noisy but still hard to miss. Watch backup configurations. Every Sunday, read restocks.csv and send something like “Restocks this week: 3, mostly Tue–Thu between 7 and 9am”. That turns the log into something you can act on, since you’ll know when to be ready. Pickup window in the alert. Apple’s data sometimes says when it’ll be ready, like “Today” or “Tomorrow”.
